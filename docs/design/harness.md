# The harness

- **A repository's rules are its guideline files and the files they link.** A root `CLAUDE.md` or `AGENTS.md` is often an index: megareviewer's own is 310 bytes and names the documents with the rules in them. So megareviewer finds a repository's **harness**: the five guideline files and, from each, what it imports (`@docs/rules.md`), links in Markdown or names in prose, a `.md`, `.mdc`, `.markdown` or `.txt` file of the repository's, or a folder, which brings the Markdown under it. A folder is named as often as a file: graal's `AGENTS.md` says documentation lives under `docs/`, and pytorch's `CLAUDE.md` names `torch/distributed/` before the `AGENTS.md` in it. A code span that holds a path and nothing else names it, since those two are both in code spans; a fence and a span with more in it are examples, as every code span was in the first version, which caught neither. Outside a Markdown link a folder ends in a slash, starts with one or with `./`, or is a code span's path with a slash in it, as spring-framework's `AGENTS.md` names `framework-docs/modules/ROOT`, so `I/O` and `before/after` in prose are no folders, or ends in a pattern for its Markdown, as an index's table writes one: `/docs/conventions`, `/docs/conventions/` and `/docs/conventions/*` all name it, the leading slash for the repository's root, as a Markdown link has. A code span's `docs/plan` without its slash was no folder in the version before, for a branch such as `feature/login`, which now costs a lookup that finds nothing. Every file named is walked before a folder brings any, so a folder of a thousand files crowds out no file a guideline links: graal's 14 suites, each named as a folder, filled the 200 files at the first hop and left out 53 docs that files further from the root link by name. A folder's `.txt` files are left out, since in one they're licenses and notices more often than rules. Every Markdown file in the repository was the alternative: of megareviewer's 104 that adds the eval cases' fixture files and each adapter's `PROVENANCE.md`, which are nobody's rules. Links alone already reach 81 files and 1 MB there, since `CLAUDE.md` names the plan README, which links every stage doc, so being reached isn't being read: an import is the author saying "always load this", and is in every review while it fits; the rest, and what doesn't fit, a pass opens for itself when the change calls for it, with a reader of those files and nothing else. Never a tool was the rule before, and is still the rule for everything a PR could aim at. On the evals the passes read the file a change called for, and nothing in what they read was wrong (`evals/reports/2026-11-25/harness-reader-fixed.md`), so with the agents' files on, every review that has one can read what it links: the index costs each pass a line per file, and a file costs only when a pass opens it. Every read is in Run details, and a point is marked with a file only when its pass was given it or read it.

- **What's never a repository's rules is left out of its harness, however it's named.** Reading names in prose and folders guesses, and on megareviewer's own repository it guessed wrong: the plan README names `evals/`, which brought the eval cases' copies of other repositories' files, delphi-code's `CONTRIBUTING.md` among them, so a pass could have marked a finding with another project's rule; a stage doc named a grammar's `PROVENANCE.md`, which linked eight license texts. So a link or a path in prose never brings test data (a `fixtures`, `testdata` or `__snapshots__` folder), another project's files (`vendor`, `_vendor`, `third_party`, `node_modules`), a license, a notice, a code of conduct, a changelog, a `.txt` file, or what `.gitattributes` at the base commit marks generated or vendored; an import still does, since the author said "load this". And only a guideline file names a folder: the two that made folders links, graal's `AGENTS.md` and pytorch's `CLAUDE.md`, are both roots, and every folder that brought a wrong file was named by a file further in, which says where code lives, not where rules are. Folders from an import too was the alternative: `ARCHITECTURE.md` is imported and names `src/` and `evals/reports/`. Every test file by the rule prep uses was another, and would lose `test/README.md`, often how a repository's tests are written, and pytorch's `test/REVIEW.md`. A file of megareviewer's own for what to leave out was a third: `.gitattributes` already says what's vendored, and megareviewer's marks the eval cases' copies. Since a rule like these regresses without anyone seeing it, the harnesses of megareviewer, graal and pytorch are recorded and walked in a test, which holds what each brings and that nothing in it is what's never rules. What's still read wrong: a project vendored under a folder of any other name, such as pytorch's `qnnpack`, whose own `CONTRIBUTING.md` comes in; a folder with a `LICENSE` of its own is another project more often than not, which is the rule to try next.

  Each file has a switch of its own and is on unless switched off, but only through a root that's on: a root's switch is the reviewer's say on everything it brings, the roots it imports among them, straight or through the files it imports, so a `CLAUDE.md` that is only `@AGENTS.md` brings `AGENTS.md` when it's on, unless `AGENTS.md` itself is switched off. A root another one only links or mentions keeps its own switch and default. Every root by its own switch alone was the first version, and such a `CLAUDE.md` brought nothing. Loading starts when a PR is opened, so it's there when the reviewer asks for an AI review, and nothing waits for it or fails with it. Loading on Request AI review was the first version: the run then starts with requests to the host. The preferences page shows what a root brings before it's switched on, and Request AI review's tooltip what a run would read, since a reviewer who pays for every token shouldn't learn from the bill what `CLAUDE.md` links. A file two roots reach is listed once, under one of them, with one switch, and a root goes on through another root only as that root's row, since a `CLAUDE.md` that is only `@AGENTS.md` otherwise lists all of `AGENTS.md`'s files again.

- **A file with the same content as one a review already has isn't given again.** A team that keeps one file for each agent often keeps the same text in two of them, and both whole in the prompt pay for the same rules twice and leave less of the 64 KB for the rest. So of the files a run would use, one whose git blob is an earlier one's is left out, the roots and their imports first, so a duplicate is never the one in the prompt, and the roots in their order, so of an `AGENTS.md` and a `CLAUDE.md` with the same text the review keeps `AGENTS.md`, which every agent reads, and `CLAUDE.md` is the duplicate, unless `AGENTS.md` is switched off; without a harness, the roots alone are compared by their content. A symlink was already read once on GitHub, whose listing has it as a link. Only the same bytes: two files that mostly say the same thing are both given, since telling which differences matter is the model's job, not a rule's.
