# Releases

Versions are published to npm from CI: pushing a `v*` tag runs every check, builds the package, and publishes it with npm provenance. Users can verify that a version was built from this repository at a given commit, which matters for a tool that holds their credentials. Publishing from a laptop was the alternative; it's simpler, but nothing ties the published files to the source. megareviewer is MIT-licensed.

`install.sh`, at the repository's root and piped from GitHub, checks Node and installs the command from npm by default, with `npm install -g`, into `~/.local` when the global prefix isn't writable rather than asking for sudo. Some reviewers can't take a version from npm until it's hours old, a policy of their employer's, so each release also packs the same package for its GitHub release, as `megareviewer.tgz`, with a build provenance attestation of its own. A separate job with the only write access to the repository creates the release, so no installed code runs with it. With `MEGAREVIEWER_SOURCE=github` the script downloads that file, verifies it with `gh attestation verify` against the release workflow when the GitHub CLI is signed in, unpacks it into `~/.local/share/megareviewer` and links its `cli.js`: the package has no dependencies, so that's the whole install. Verifying without `gh` was the alternative, and would mean a Sigstore client in a shell script; without `gh` the script says the file wasn't verified. A checksum file beside it was rejected: it comes from the same place as the file, so it proves nothing a download error wouldn't already show. The preview builds before npm were a tarball on a release too, with nothing attesting it.
