# Main page, connections and preferences

**PR picker.** The main page: a field for a pasted PR link, the PRs waiting for the user's review and their own open PRs from every configured host, and their review activity. A link without `https://` is read as one, and the field says what's wrong only when it's submitted, so Review is never disabled without saying why. PRs opened here before join the ones waiting for review: the 50 most recently analyzed, asked about on their hosts so only open ones show, and listed once, with the host's role, when the host lists them too. The host's list alone left out a PR opened from a pasted URL, one on GitHub once the reviewer had submitted a review, and one on Bitbucket in a repository past the 50 scanned. Keeping every PR opened, whatever its state, saved the requests, and would list merged PRs as waiting. When the lookup fails, the host's error banner says so and its own list still shows. Each list is one Tab stop, with the arrows, Home and End inside it. A row is a link to its PR's address on this server, `/pr/github/acme/api/902`, which stands for the PR before its analysis exists: opened, it starts the analysis and replaces itself with `/review/<id>`, so Back skips it. A plain click on a row still starts in place, with the row's own progress; any click a browser would open in a new tab opens the address there, and the main page stays. The link field does the same with ⌘↵, or ⌘- or a middle click on Review. Rows were buttons before, so a second PR open at once meant a new tab, which then needed the terminal's link (see [Local server security](credentials.md#local-server-security)). The analysis's own path, `/review/<id>`, was the alternative, but the ID exists only once the host has answered. The lists are read when the page opens, on Retry, on Check again, and when the tab comes back more than 2 minutes after the last read; a Refresh button was the version before, and reading on every focus was the alternative, since Bitbucket's list is a request per repository on a limit shared with reviews. A start, from the field or a row, can be cancelled: only the waiting stops, since the server can't be, and an analysis it started anyway is cached for next time.

**Between pages.** Each page keeps its place in its entry of the browser's history: how far it was scrolled, saved once the reviewer stops scrolling and before a link is followed. Back, Forward and a reload put it back once the page has drawn what it shows, a review's skeleton not counting, and then hold the line of code at the top of the window while what's above it loads, as the landing does, until the reviewer moves or 5 seconds pass. A link opens its page at the top. The browser's own restoration was the version before: it ran before the review had loaded its analysis, so Back from the preferences put the reviewer near the top of a long PR, and a link opened the next page as far down as the last one was. A place per analysis, kept in `sessionStorage`, was the alternative; two entries of one review, such as before and after Next, would share it. A tab in the background draws nothing, so one left there for those 5 seconds after Back stays at the top. A link to the preferences from a review opens the panel of what it names: a preference's own scope, a guideline file's repository, the scope a rule saved from a point went to, and from Run details the PR's repository. The header's link opens Everywhere's.

**Connections** is a button in the header of every page, with a popover of GitHub, Bitbucket, Claude, Codex, opencode and Jira: whether each works, the error when it doesn't, and the variables that would connect it. It replaced the header's status dot and a setup strip on the picker, which showed four lines on every visit to a reviewer whose setup works. megareviewer holds no credentials of its own, so the popover has no Connect or Manage, only Check again, which reads the status and the lists again; entering credentials in the page would need a store for secrets. Each tool that runs Request AI review is a row of its own, Claude on Claude Code or the API, Codex and opencode, so a reviewer sees what each would add and how to connect it, rather than only the one the default model runs on; one that can't run is optional, not an issue, since the review works without the model, and its fix is its providers' reasons. Its row says only Not connected: every one of them is optional, so the word on each said nothing. One row for the model was the version before, named after the default's family, and never said Codex or opencode could be connected. `connectionsOf` in `web/src/app/connections.ts` is the pure function from the status to the rows and the button, and the status is read once for every page, in `ConnectionsProvider`.

**Review activity** is a calendar under the lists of what the reviewer posted from megareviewer on this machine: a square per day for 26 weeks, or as many as the card fits down to 8, shaded by pull requests reviewed, with the comments in each square's tooltip and name, and totals beside it. `GET /api/review-activity` returns the last 27 weeks' timestamps, one week of margin for the time zone, and the page sorts them into the browser's local days, since a day's edges depend on its time zone. It's derived from what publishing already records, not written twice: a review is a row of `publications`, its comments the rows of `published_comments` but the summary, and both are already the idempotent record a retry relies on, so a retried publish can't count twice. Replies and Comment now were recorded nowhere, so `thread_posts` keeps one row each, written once the host accepts them; a post whose answer was lost isn't counted, since nothing says it landed. A table of activity events beside the others was the alternative: two writes to keep in step on a publish that isn't atomic on Bitbucket.

**Preferences page.** `/preferences`, from a link in the header of every page, beside Connections. A page, not a popover: it holds lists the reviewer edits, and the model's choice was kept off a settings page only because it was one field. Under 640px the link is its icon. The scopes are listed on the left, Suggestions and Everywhere, then under "Repositories" each repository megareviewer has analyzed or holds a preference for, and the panel beside them is one scope's; a label over the one Everywhere row was the version before, saying what its row already says; under 1024px the list is a select above the panel. A stack of one card per scope was the version before: every repository said it had no preference yet, with its guideline files and Import again, and the reviewer scrolled past them all to the one they came for. The scope is in the URL's query, `?scope=github/acme/shop`, so a reload and Back keep it, and choosing one moves the focus to its panel's title. A row counts a scope's preferences, on or off, and Suggestions the proposals waiting, only above zero. A repository's row is its host's mark, GitHub's or Bitbucket's from Simple Icons (CC0-1.0, in the package's notices, since lucide has neither), and its name without its owner, cut in the middle at a `-`, `_` or `.` to fit, as the tree cuts a file's name; its whole name is in a tooltip and its accessible name, and its owner shows only where another repository listed has its name.

A panel is, in order, its proposals, its preferences, one muted line saying it has none when a scope has neither, the form, and a repository's guideline files; a part with nothing in it isn't drawn. A sentence saying what a preference is, with both kinds' chips in it, was the version before, and on a repository with nothing yet a dashed box offering Suggest and Import: the form and the title's line, that Everywhere's preferences come first, already say it. Suggestions' panel lists every proposal, grouped by the scope it would apply to. A proposal is its kind, its rule, the evidence it rests on, Add, which accepts it as it reads, and Dismiss, which rejects it; one over 300 characters opens in the form on Add, since a preference is one sentence. Reject, Edit and Accept was the version before; a proposal is edited once it's a preference, as any other is. A preference is a row: its kind as a word with a glyph, its rule, "From your reviews" when it was learned or imported, its switch, and Edit and Delete as icon buttons. Edit and Delete behind a "…" menu was the version before, two clicks to either; the design's row without the switch was rejected, since switching a rule off is how a reviewer tries a review without it and how the 50-enabled limit is met. The form is always open under its own heading, one row: the kind, a field one line high that grows with its text, its label for screen readers and its example as the placeholder, and Add preference. The panel is its scope; editing a preference and saving one from a point keep a scope select. A card around it, with a visible label and a scope select, was the version before, and before that a form behind an Add preference button in each card. The rule is one line; Enter saves, and an empty rule or the server's refusal is said under it. Its count, of 300, shows from 250 characters, and over 300 it turns red, a line says by how much, and Add preference is disabled, focusable and described by that line. A count always shown was the version before, a number to read on every rule, and so was saying what's wrong only on saving, never by a disabled button: the count says it before the click, and a disabled button that says why is as clear.

Suggest from my reviews is in a repository's panel header, whatever the panel holds, and nowhere else: one split button whose arrow opens the model options, the same choice as Request AI review's, kept per browser, so a model chosen here is the one Request AI review runs too. A choice of its own for the suggestion calls was the alternative, a second setting to keep apart from the first; the page without one, where only the review page's arrow chose, left a reviewer who opened Preferences first no way to change the model. The design's arrow chose between this repository and all of them, and was rejected for the model's. Its tooltip and description say what it reads, which model and who pays; when no model can run, it's disabled, focusable and says why there, with no line under it. Suggest on every panel with Import beside it on a repository's, and both in a box under what a preference is when a repository had nothing yet, was the version before, Suggest disabled until something new was recorded. What a run came to is said under the panel's title, “Read 92 comments from 30 pull requests and 14 actions recorded here: 2 suggestions, 1 for Everywhere and 1 for acme/shop.”, and stays until the next run, since the page keeps it rather than the panel; a toast was the alternative, gone before the reviewer has looked at where the suggestions went. A repository's panel lists its guideline files with their size, a switch and how a review uses each, “In every review”, “Read when the model asks” or “Ignored”. The words name no transport, since which one runs is the run's to say. A file of any size has its switch: one over the prompt's budget is read when the model asks. A file too large named as such with no switch was the version before, when only the prompt could hold one, and what it imported couldn't be switched on.

A guideline file that links others has a second line, “7 linked files, 88 KB” and how a review uses them, “2 in every review, 5 on request”, which opens to them by the file that links each, with a switch on each; a root that's off says what it would bring, “When on: …”, so the reviewer knows what switching `CLAUDE.md` on means before doing it. Folded, because megareviewer's own harness is 73 files and a list always open would bury the preferences above it. A linked file is on unless switched off, and one that's on behind a file that's off says “Ignored: links to it are off”; off by default was the first design, from before the reader, when a linked file cost the prompt its whole text rather than a line of the index. A guideline file another one links has no second switch, only its own row's, which shows on where an enabled root imports it. Under the list is what it doesn't have: a limit the links reached, each file too large or not text, and a load that isn't in. With none it says “None found at the repository's root.”, the five names it looks for behind an info button's tooltip and description rather than in the sentence.
