# megareviewer

Follow ENGINEERING.md on every change.

[DESIGN.md](DESIGN.md) says what we're building and why: read the decisions on what you're changing before you change what the product does or how a page behaves. [ARCHITECTURE.md](ARCHITECTURE.md) says how it's built: read the section on a component before you change it. Both record the alternatives rejected, so a choice isn't made again without its reason.

The implementation plan is in docs/plan/README.md. When you're given a stage, follow its doc and the plan README's rules for picking up a stage.

In the UI, add text or a keyboard shortcut only when it's really needed or I ask for it. A label, hint, empty-state line or key that says what the page already shows is noise: leave it out.
